# 導入格式

所有文件採 UTF-8。單次導入上限為 2 MB；大型語料可按篇分開。標註內容使用 tshet-uinh 的音韻地位描述，不是全拼字串或三拼鍵碼。

## polyhedron 原文／拼音行

在導入格式選擇「polyhedron 原文／拼音行」，例如：

```text
子曰、學而時習之、不亦說乎。
cix yat: ghruk nji zji zsip cji, pyot jek jyet gho?
```

音節按原文漢字對齊，保留標點、換行、原始拼音與選讀。支援連字號、行尾 `#` 備註、`yonh/ynh` 多讀、`leu(lek?)` 疑讀和 `???` 缺讀。帶原始 polyhedron 檔頭的《論語》可自動識別來源與許可；無檔頭的自選文本需自行填寫。原文與音節數不一致時導入會提示位置並停止，不能靠刪字或補音節強行配對。

純拼音《唐詩三百首》不能直接逐字導入，請在「語料」頁使用已配對原文的內建版本。大型內建資料包由網站載入，再按篇加入與匯出，不受手動單次文件導入的 2 MB 限制。

## TXT

```text
春(昌合三真平)曉(曉開四蕭上)（孟(明二庚去)浩(匣開一豪上)然(日開三仙平)）
春(昌合三真平)眠(明四先平)不(幫三C尤上)覺(見二江入)曉(曉開四蕭上)，
處(昌開三魚去)處(昌開三魚去)聞(明三C文平)啼(定開四齊平)鳥(端開四蕭上)。
```

首行若符合「標題（作者）」或以 `# ` 開頭，會作為標題資料，不加入練習正文。中文外括號中的作者姓名標註會去除。一般正文的中文括號原樣保留；`字（音韻地位）` 也可識別。多讀用 `|` 分隔，例如 `聞(明三C文平|明三C文去)`；不標註的漢字需要人工補填或跳過。

「TXT 空行分篇」適合整份 nk2028 標註語料。若文章內的空行只是分段，請取消該選項。直接從檔案導入後，需先識別並檢查預覽，再保存。

## TSV

每列一個 Unicode 字元；非 BMP 漢字也計作一個字元。欄位可使用 `字`／`音韻地位` 或 `char`／`position`，無標題列時採第一、第二欄。

```text
字	音韻地位
韻	云合三C文去
，
切	清開四先入
```

標點可以放在獨立資料列，音韻地位留空。多讀同樣以 `|` 分隔。

## JSON

推薦使用本站匯出格式。可導入單篇物件、多篇物件陣列，或 `{ "documents": [...] }`。

```json
{
  "title": "示例",
  "author": "",
  "source": "人工標註",
  "license": "",
  "tokens": [
    { "char": "韻", "position": "云合三C文去" },
    "，",
    { "char": "聞", "positions": ["明三C文平", "明三C文去"] },
    { "char": "曉", "positions": [] },
    "。"
  ]
}
```

`position` 是已選讀音，`positions` 是原始候選。`confirmed: true` 表示使用者已確認字典未收讀音；無效的音韻地位仍會被列入校對。`skip: true` 跳過該字。匯出文件中的 `audit` 保存選讀修改與跳過記錄。

轉換語料另保留 token 的 `sourceReading`、`conversion`，以及文章的 `category`、`provenance`（來源版本、原始拼音、原文配對來源、對齊問題）。這些欄位會在匯出重讀與本機保存後保留。`conversion: "ambiguous"` 即使只剩一個字庫候選，也仍須明確確認原作者的疑讀。

另一種接受格式是 `text` 加 `annotations`：

```json
{
  "title": "Unicode 索引示例",
  "text": "𩦠韻。",
  "annotations": [
    { "index": 0, "char": "𩦠", "position": "並三A陽上" },
    { "index": 1, "position": "云合三C文去" }
  ]
}
```

`index` 從 0 開始，以 Unicode 字元計算，包含標點與換行，不能使用 UTF-16 程式碼單元索引。可填 `char` 作為對齊核對。

補充「怎」的音韻地位標記為 `補充:怎`。原文不會做簡繁轉換，以免改動異體字及逐字標註的對應。
